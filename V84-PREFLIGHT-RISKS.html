V8.4 执行前风险检查

实话实说：哪些能跑，哪些有坑

🔴 确定不行、必须改的

1. 每个租户一个独立子进程 — 1GB VPS 撑不住

方案里写的：child_process.fork() 每租户一个独立进程 → 物理隔离
实际：每个 Node 子进程约 30-50MB。30 个租户 = 900-1500MB，还没算 Master 和操作系统。1GB VPS 跑不了。

修正方案：一个进程 + 文件系统隔离。不是"进程隔离"，是"数据隔离"。每租户的 KB 目录分开，代码里禁止跨租户访问。95% 的 SaaS（包括 Intercom 早期）都是这么干的。1GB VPS 可以跑 50-80 个租户。
2. 微信/支付宝收款 — 个人身份可能开不了

方案里写的：微信/支付宝扫码收款
实际：微信支付商户号需要企业资质。支付宝当面收可以用个人。Stripe 支持 Alipay 作为付款方式。

修正方案：需要你确认——你目前有没有支付通道？用 Stripe 收 Alipay 是最简单的（Stripe 已装好），走 WeChat 可能要用 PayJS 这类聚合支付。
3. DeepSeek API 线上表现跟预览完全不同

方案里写的：预览版对话跟线上一样
实际：预览是写死的模拟。线上用 DeepSeek API 会有：延迟 2-5 秒、偶尔偏离提示词、可能拒绝回答、费用按用量走。

修正方案：Phase 1 先不搞全功能。先接上 DeepSeek 跑 10 条真实对话，验证延迟、质量、成本。确认可行再往下做。

🟡 有风险但能解决的

4. 自动扫描网站建 KB — 不太靠谱

很多 WooCommerce 站点没有标准页面。先只做 WooCommerce API 自动同步（可靠），网页扫描当 bonus。
5. Dashboard 工作量被低估

6 个栏目实际是 600-1000 行代码，2-3 天。Phase 2 只做核心 3 个栏目（产品 + FAQ + 订阅），分析放 Phase 3。
6. $20/年 VPS 跑生产有风险

RackNerd 的 $20 套餐 CPU 一般。初期够用。如果性能不够，升级到 $5/月 DigitalOcean（$60/年，好很多）。

🟢 没问题的

• ChatWidget 组件 — 200 行标准 React ✅
• Master + WebSocket — 标准 Node.js ✅
• HMAC token + 域名白名单 — 标准安全模式 ✅
• SQLite — 对几十个租户够用 ✅
• 7 天试用 — 两个字段的事 ✅
• 对话日志 — 30 行代码 ✅
• WordPress 插件 — 150 行 PHP ✅
• 每日分析 LLM 调用 — 100 行代码 ✅

最终 verdict

框架本身是对的，产品逻辑也没问题。但 3 件事必须在 Phase 1 前搞清楚：

1. 进程隔离 → 改单进程 + 数据隔离（不改物理隔离了，1GB 撑不住）
2. 收款方式 → 你确认目前有没有能收微信/支付宝的通道
3. AI 线上表现 → Phase 1 先接 DeepSeek 跑 10 条对话，不直接铺开

这三件定了，剩下的都是标准开发工作，没有不可控风险。
