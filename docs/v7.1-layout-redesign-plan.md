## 一、三重结构分析

### 1.1 结构分析（组件树 + JSX 嵌套）

当前页面布局（确认已部署的当前代码）：

```
ProductPage
├── Breadcrumb
├── Loading Skeleton
├── Product Content (!loading && product)
│   └── Grid (2列: image + details)
│       ├── LEFT: 产品图片占位
│       └── RIGHT: 纵向堆叠
│           ├── 标题/价格/按钮
│           ├── 信任徽章 (3列grid)
│           ├── Product Details (specs) ─────────┐
│           ├── How It Works (3步) ──────────────┤ 需要互换位置
│           ├── Features (条件渲染) ─────────────┤
│           └── System Requirements (条件渲染) ──┘
├── Comparison Table (条件渲染)
├── FAQ (条件渲染) ───────── 需要去掉 max-w-7xl 包装
└── Reviews (条件渲染)
```

共引用的文件：
- `src/pages/Product.tsx`（主文件，需修改 JSX 布局）
- `src/components/ProductFAQ.tsx`（需修改：去掉外层 wrapper）
- `src/index.css`（无需修改）

### 1.2 行为分析（数据流 + 状态）

```
slug (URL参数)
├── fetchProduct(slug) ──→ product state
├── PRODUCT_DETAILS[slug] ──→ details ──→ features, requirements 条件渲染
├── COMPARISON_MAP[slug] ──→ compGroup ──→ ComparisonTable 条件渲染
├── FAQ_SERIES_MAP[slug] ──→ sKey + allFaqs ──→ FAQ 条件渲染
└── woo-ids 映射 ──→ reviews API ──→ reviews state ──→ Reviews 分页渲染
```

关键风险点：
- `compGroup`、`allFaqs` 在组件初始化时就计算，不在 product block 内。所以即使移到外面也没问题 ✅
- `details` 在 `product` 存在时才活跃。Features 和 System Requirements 移到 product block 内部，没问题 ✅
- `features` 变量名冲突：组件内 `const features = [[...]]`（fallback specs）和 `details.features`（实际功能列表）是不同的

### 1.3 样式兼容性分析

现有样式模式：
| 区块 | 容器类 | 内部布局 |
|------|--------|---------|
| Product Details | `border-t border-[#e8e8ed] pt-6` | `flex justify-between` 行 |
| How It Works | `border-t + grid grid-cols-3` | 3列圆形步骤 |
| Features | `grid grid-cols-1 md:grid-cols-2 gap-2` | 卡片+图标 |
| System Requirements | `bg-[#f5f5f7] rounded-xl p-4` | `flex justify-between` 行 |

已知限制：
- Rolldown 解析器对 `{...{...}...}` 深层 JSX 嵌套会报错（brace counting bug）
- 所有条件渲染使用 `{condition && <JSX/>}` 模式是安全的
- 避免在 JSX 属性中使用 `{...}` 嵌套表达式（如 `className={"a " + (b ? "c" : "d")}`）

## 三、风险评估

### 3.1 已知风险

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|---------|
| Rolldown brace nesting 触发 | 中 | build 失败 | 避免嵌套 `{...{...}}`，所有条件渲染用简单 `{cond && <JSX/>}` |
| features 变量名冲突 | 低 | 显示错误 | 确认组件内 `features` 是 fallback 数组，`details.features` 是功能列表，不同名字空间 |
| Features 或 Req 单独缺失时布局断裂 | 中 | 半空白列 | 添加 `col-span-full` 当一侧为空时的回退逻辑 |
| How It Works 从内联 HTML 拆分到独立 div | 中 | 样式变化 | 保持所有 Tailwind 类不变，仅改 wrapper 层 |
| 移动端响应式 | 低 | 单列堆叠 | `grid-cols-1 md:grid-cols-2` 自动处理 |

### 3.2 影响范围检查

需要修改的文件及影响：
1. `src/pages/Product.tsx` — 仅影响 Product page 的 RIGHT 列 JSX。不影响 Home、About、B2B 等页面。
2. `src/components/ProductFAQ.tsx` — 去掉 `max-w-7xl` wrapper。仅影响 FAQ 组件自身的宽高。
3. 其他 SPA 页面（Home.tsx、MainApp.tsx 等）：**零影响**，Product page 是独立路由 `/product/:slug`。

数据文件（faq.ts, product-comparison.ts, products.ts）：**零修改需求** ✅
样式文件（index.css）：**零修改需求** ✅（所有类名已存在）
其他组件（ProductComparison.tsx, ProductReviews.tsx）：**零修改需求** ✅

        ))}
      </div>

  );
}
