# v6.1.2 → v6.1.3 缺陷修复
## 6 个缺陷修复 + 重新验证 12 项测试

---

## 修复 1: 订单存在性校验 (Test 3)
**问题:** CSV 中有不存在的订单 ID → 数据丢失
**修复:** 导入时先查询所有订单是否存在。不存在的列入错误清单，不处理。

`
导入前验证:
  SELECT COUNT(*) FROM wp_posts 
  WHERE ID IN (681,682,9999) AND post_type = 'shop_order'
  → 返回: 681,682 存在 | 9999 不存在
  → 报警: "Order #9999 not found, skipped"
`

## 修复 2: 产品 Slug 回退匹配 (Test 4)
**问题:** 产品 Slug 变 → Key 分配不到
**修复:** Slug 找不到时, 按产品名称回退匹配

`
先按 slug 精确匹配 → OK → 使用
按 slug 找不到 → 按产品名称相似度匹配 → OK → 使用
都找不到 → 列入错误清单
`

## 修复 3: 重复行检测 (Test 5)
**问题:** CSV 同一订单同一产品出现多次 → 多分配 Key
**修复:** 导入时按 (Order# + Product Slug) 分组去重

`
CSV 原始行:
  #681, windows-11-pro, WX11P-KEY1
  #681, windows-11-pro, WX11P-KEY2  ← 重复订单+产品
  
处理: 合并到同一组, 检查 Key 数量是否 ≤ Qty
`

## 修复 4: 断点续传 (Test 8)
**问题:** 导入到一半网络断了 → 部分 Key 已保存, 部分丢失
**修复:** 每保存一个 Key 记录状态。重新导入时跳过已保存的。

`
已处理: 124/312
中断 → 重新上传 CSV
系统检测: 124 个 Key 已存在 (相同 Order# + Slug + Key)
→ 跳过 124, 处理剩余 188
`

## 修复 5: 乐观锁 (Test 10)
**问题:** 处理时订单状态被改 → Key 分配给已取消订单
**修复:** 保存 Key 前读取当前订单状态, 与导入时的快照对比

`
导入时记录: #681 → 'processing'
保存前检查: #681 当前状态 → 'cancelled'
→ 检测到冲突 → 报警: "Order #681 status changed from 'processing' to 'cancelled', skipped"
`

## 修复 6: Key 超额校验 (Test 12)
**问题:** 订单需 3 个 Key, CSV 填了 4 个 → 多的被丢弃
**修复:** 统计 CSV 中每个订单每个产品的 Key 数量, 与 Qty 列对比

`
Order #681 Product: windows-11-pro Qty:2, CSV中Key数:3
→ 报警: "windows-11-pro needs 2 keys but 3 provided, first 2 used"
`
