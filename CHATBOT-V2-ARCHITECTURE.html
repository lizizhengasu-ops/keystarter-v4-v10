一、三门户架构（谁是给谁看的）

🏛️ 管理后台

admin.你的域名.com

只有你能看到

  • 查看所有租户列表
  • 管理订阅、价格方案
  • 跨租户数据分析
  • 租户切换器（你可一键切换看任何客户的后台）
  • 系统设置：AI模型、费率

👤 客户后台

dashboard.你的域名.com

付款客户登录后看到

  • ⚠️ 续费横幅（到期前10天每天显示）
  • 订阅卡片：剩余天数、用量
  • 知识库管理（上传产品/FAQ）
  • 聊天浮窗样式配置
  • 使用分析
  • 账单和付款历史

💬 聊天浮窗

嵌入客户网站

网站访客看到

  • 右下角聊天气泡
  • AI 回复（仅基于知识库内容）
  • 自动转邮件没人回答时
  • 看不到任何账单/租户/管理信息
  • 看不到任何代码内部——就一行 <script>

⏱️ 计时原理

注意：计时在你服务器上，不在客户网站。

  • 客户付了款 → 服务器记下 expires_at
  • 客户网站不知道什么时候过期——它只是每次发消息时问服务器"我还能用吗"
  • 服务器说"过期了"→ 浮窗就停用了
  • 客户改不了本地时间，也绕不过去

🚩 续费横幅逻辑

  • 横幅出现在客户后台（dashboard），不在聊天浮窗里
  • 到期前10天 → 每天登录 dashboard 都看到黄条
  • 点击续费 → Stripe 再收一次 → 自动加30天
  • 客户的网站访客永远看不到任何续费信息

五、反破解（怎么保护你的代码）

客户网站上有啥？

就一行

<script src="https://chat.你的域名.com/w.js" data-t="加密字符串" defer></script>

没有 API key、没有 AI 逻辑、没有知识库、没有你的商业逻辑。 客户拿到的只是一段被压缩混淆到无法阅读的 JS。

6 层防护

  1. 代码混淆：esbuild + terser 压缩成乱码，不产生 sourcemap
  2. Token 加密： data-t 里是 HMAC 签名，只有你服务器能解密出租户身份
  3. 域名白名单：服务器检查 Origin 头，不在名单的直接返回 403
  4. JWT 短时效：每次连接发 2 小时有效的 token，超时重新签发
  5. 限流：每个租户每分钟最多 30 条消息
  6. CORS：只允许白名单域名跨域连接

八、部署路线

Phase 1（3-4 天）

  • Chat Widget 浮窗（vanilla JS, Shadow DOM）
  • Master 主进程 + Worker 工人模板
  • WebSocket 通信
  • 租户配置管理
  • 可用的聊天服务（纯 RAG，不含用户门户）

Phase 2（2 天）

  • Stripe 收款对接
  • 订阅计时 + 自动过期
  • 续费流程
  • 域名白名单 + 反破解

Phase 3（5 天）

  • 客户后台 (dashboard.*) 全部功能
  • 管理后台 (admin.*) 全部功能
  • 知识库管理界面
  • 分析面板
  • 上线第一个真实客户
