二、两条产品路径

路径 A：WordPress 插件

PHP 插件
目标：已有独立站的中国老板
他们做什么：下载安装插件 → 扫码付款 → 机器人出现
你做什么：维护 WordPress.org 上的插件 + 后端服务
插件代码量：约 300 行 PHP（简单位），加上你的 Node.js 后端（已有）
上架：WordPress.org 插件仓库（审核 1-2 天，免费发布）

路径 B：预嵌入全站建站

React 组件
目标：需要建新站的中国老板
他们做什么：你建站 → 机器人已经在里面 → 后台付钱开通
你做什么：建整套独立站 + 后端服务
组件代码量：约 200 行 React（ChatWidget.tsx）
同样连到：你的 VPS 上的 chat service
两条路共用的后端完全一样：
插件和预埋组件都连到 chat.你的域名:3002，同一套 Master + Worker + 计费 + 知识库。
插件用 PHP 输出 script 标签。预埋是 React 组件直接 WS 连接。殊途同归。

✅ 两条路可以同时走

3.2 Quorlyx 能不能直接搬过来用？

Quorlyx（GitHub 5⭐，PHP 写的 WordPress 插件）

模型差异：Quorlyx 是 BYOK（Bring Your Own Key）模式。客户安装插件后自己填 OpenAI/其他 API Key，AI 费用客户自己付。你没有中间利润。

你的模式：ChatWidget/插件免费，客户付订阅费给你，你统一用 DeepSeek API 处理 AI。DeepSeek 成本你承担（约 $0.5/月/客户）。

能直接搬吗？
代码上 MIT 协议可以搬运。但搬了也没用——它不解决你的核心问题：它没有集中式多租户后端，没有计费系统，没有物理隔离。

可以做什么？
参考它的 WooCommerce 数据对接方式（如何读商品、订单）。这部分技术可借鉴。

利用信息差给中国老板？
中国老板不会上 GitHub 搜 Quorlyx。你的竞争不是 Quorlyx 本身的知名度，而是你得给中国老板一个他能理解的、能用微信付钱的产品。他不在意后端是谁的技术。

3.3 Tidio 的 AI 有什么？

Tidio AI（$29/月起，500 次对话/月）

AI 功能：
• 自动回复常见问题
• 根据对话内容建议回复
• 产品推荐（跟购物车数据联动）
• 订单查询自动回复

跟你的差距：
• Tidio 的 AI 是封闭的，你不能定制它回答的内容边界
• Tidio 没有「仅基于知识库回答」的硬约束
• Tidio 不接受微信/支付宝
• Tidio 没有客户聊天记录单独面板

你的优势不是 AI 多强大，是你的 AI 只回答知识库里的内容、能用微信收款、客户能看聊天记录。

四、技术方案：两条路 + 一个后端

4.1 WordPress 插件方案

插件功能：
安装后 → 在 WP 后台左侧菜单加一项「AI 聊天机器人」→ 点进去显示：
• 注册/登录页面（首次）
• 套餐选择 + 微信/支付宝扫码付款
• 状态页面（已激活/剩余多少天/续费）
• 前端网页加载 ChatWidget

技术细节：
• PHP 70% + JavaScript 30%
• 主要用 WP 的 REST API 和 Shortcode
• ChatWidget 用 vanilla JS（不依赖 React，兼容所有主题）
• 跟你的 VPS 通信（HTTPS API + WebSocket）

插件代码量估计：
• PHP 插件主文件：~150 行
• 后台设置页面：~100 行
• ChatWidget JS：~200 行（与 React 版本功能相同）
• 总计：~450 行

4.2 预嵌入方案（已有的）

React ChatWidget 组件，预埋在 SPA 中编译。跟你之前讨论的一致。
不改 WooCommerce 任何后端代码。

4.3 后端共享

两个方案共用同一个后端服务：

插件版连接

客户 WP 网站 → 加载插件输出的 JS → WebSocket → 你的 VPS

预埋版连接

客户 SPA 网站 → React 组件 → WebSocket → 你的 VPS
后端服务完全相同，不走两套。

七、怎么做？先干 2-3 个客户

先做 A 还是先做 B？两种都做，但顺序有先后。

第一步：建站含 chatbot（路径 B）
• 先以「建站 + chatbot」的方式服务第一个真实客户
• 你给他建站，预埋 ChatWidget，他付月费
• 目的是测试：真的有人愿意付 ¥299/月 吗？
• 同时验证：后端服务稳定吗？AI 回答靠谱吗？客户真的会用吗？

第二步：做成 WordPress 插件（路径 A）
• 第一个客户验证可行后，把 ChatWidget 拆成 WordPress 插件
• 上架到 WordPress.org 插件仓库
• 这时候你已经有：
  1 个后端服务在跑 ✅
  1 个真实客户的反馈 ✅
  一套收款流程验证过 ✅
• 插件是低成本获客渠道，不需要你给每个客户建站

第三步：两条路一起走
• 路径 A（插件）获取不能建站的客户
• 路径 B（建站）获取要全套服务的客户
• 共享同一套后端服务

八、怎么找到第一批客户

这比写代码难。实话说。

可能的方向：
1. 你在 Reddit/跨境电商群里找中国独立站卖家，问他们需不需要 AI 客服
2. 淘宝上有代建 WordPress 独立站的服务，你可以合作（你提供 chatbot 模块）
3. 你现在就有客户——你那些 kit、部署服务本身就是面向中国老板的
4. 插件上架 WordPress.org → 自然流量 → 每月可能有几十个下载

定价策略：
第一个客户免费试用 1 个月，验证他愿意在第二个月续费。然后才有说服力。
不要一上来就卖插件。先验证有人愿意付钱。
